## Scope and interpretation

The active application is a static **vanilla JavaScript ES-module / Three.js**
planner. There are no React components, hooks, TypeScript sources, application
server, accounts or server database. Bootstrap supplies dialogs; native DOM
adapters supply the editor. Vite builds the site. Separate historical planners
are still published. Files and implementation take precedence over older plans.

**Complete** means implemented for the explicitly described scope with supporting
source/test evidence, not certification on every browser. **Partial** means a
meaningful part exists but the overall user workflow or target is incomplete.
**Broken** means a concrete failing path is established. **Missing** means no
implementation was found; it does not imply a v1 commitment. **Unverified** means
the relevant runtime claim needs additional evidence.

Testing references below identify existing coverage, not tests all rerun for this
audit. `U/name` means `tests/unit/name.test.js`; `E/name` means
`tests/e2e/name.spec.js`. **Fresh** marks one of the five focused unit files run
here: `state-actions`, `history`, `numerical-transforms`, `model-imports`, and
`legacy-codec` (74 tests passed). **Probe** means a disposable, in-memory Node
check, with no production/test source modifications. Details and limits are in
the [validation ledger](V1_RELEASE_AUDIT.md#validation-ledger).

## Implemented services without complete UI

The app export is an integration boundary, not a production debug global. Tests
import that module and attach their own aliases. API-driven browser tests do not
prove that ordinary users can discover a feature.

| Capability               | Existing entry point                                                          | Missing user flow                                                            |
| ------------------------ | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Browser-local projects   | `app.projects.save/open/list/delete`                                          | Name, save, browse, reopen, overwrite/delete confirmation and storage status |
| Imported duplicate/scale | `app.modelImports.duplicateImportedObject`, `app.actions.transforms.setScale` | Duplicate action and scale fields                                            |
| Missing model recovery   | `app.modelImports.getMissingAssets/retryMissingAsset`                         | Retry URL/relink file controls                                               |
| Attribution/license      | Import service metadata argument                                              | Import form fields and provenance review                                     |
| Clear setup              | `app.actions.reset()`                                                         | Explicit clear/new scene command                                             |

These distinctions drive A-003 and the early v2 milestones; they must not be
marketed as complete end-user workflows simply because service tests pass.
